Recovering historical sequential response logs

Some archived results retain individual answers in reasoning_traces.jsonl with
message_idx, attempt, content and reasoning, but no explicit comparison/order
ID. The keyed reader skipped these records, understating response coverage.

The fallback in noise_response_inputs.py is restricted to seven reviewed
producer commits from the mint-re-engineering history. At these commits:
- run_experiment awaits each comparison in preference-array order.
- run_single_comparison awaits ten original-order trials, then ten flipped.
- generate_responses uses K=1 and preserves message_idx as the trial index.
- LiteLLMAgent appends exactly one nonempty successful response per trial,
  after retries. It awaits all trials before returning to the experiment.
- The final trace file serializes that append-only log without reordering.

Recovery is deliberately limited to complete logs. Each file must have exactly
2 * 10 * comparison_count records, each contiguous block must contain trial
indices 0 through 9 exactly once, and every comparison must reconcile with the
selected result's saved A/B totals using the production parser and correct
flipped orientation. Missing/duplicate records, unknown versions, mixed keyed
schemas, invalid success metadata and count mismatches reject the whole file.
Recorded unparseable answers remain unparseable, never invented choices. A
disagreement with an existing verified trial identity raises an error even if
the aggregate counts agree. Source code 6 identifies this recovery route.

Run validate_noisy_agent into a new directory using the updated reader, then
run repair_noisy_agent against that completed validation. Old response caches
carry the old reader hash and must not be relabeled as new validation. Keep the
same source manifest, baseline, folds, seed and minimum coverage threshold.
Neither command makes inference calls. No statistics should be updated until
both output manifests are complete and all fitted models have converged.

The response-recovery tests include arbitrary within-batch completion order,
retry metadata, flipped choices, incomplete logs, duplicate/invalid indices,
late count mismatches, unreviewed versions, mixed schemas, unparseable content,
provenance and conflicting independently saved trial identities.
